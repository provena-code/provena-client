# provena-client

An instructor-facing client to view logs generated by the [provena-server](https://github.com/thomaswp/provena-server) and [Provena VSCode plugin](https://github.com/thomaswp/provena-vscode).

Allows you to browse and replay students' work.

## Setup and Running
* Setup the [provena-server](https://github.com/thomaswp/provena-server), following instructions in its README.
* Clone with submodules
* Set up node + npm install
* Copy .env.template and set the values (API_ROOT points to the provena server's root; VITE_APP_BASE_PATH is wherever this is deployed (optional on dev))
* Run locally with `npm run dev`
* Deploy for production with `npm run build` (make sure to have the right VITE_APP_BASE_PATH for your server)

## Using

### Logging in
Currently you need to log in using an API key (this will be improved to SSO in the future). Use a key included in your server's `testing_api_keys` list in `src/write_config.yaml`.

### Browsing Assignment or Students
Currently you can browse by Assignment and by Student. Browsing by Assignment allows you to then select a Student to view. Browsing by Student allows you to select any file to view. You can also browse activity across all files over a given date range (though this is still in development and may have bugs).

### File history view

When viewing a replay, you can:
* Play or scrub through the whole history
* Turn on Provena's provenance highlighting (Highlight checkmark)
* Ctrl+click on any text in the student's code to see the approximate frame it was created
* See details of the individual logging event(s) for each frame
* See the state of the students' current clipboard (Note: this only includes text that came from students' code or was pasted into students' code for privacy.)
* See the authorship information (author, start and end time) for any span of the studnet's text


**History Generation Errors**: Provena will do its best to attribute provenance to every character in a student's code. However, sometimes logging errors make this impossible. If you see a History Generation Error, it will indicate on what frame this error occurred. Usually the errors are minor, but they suggest interpreting provenance with care.


**Note**: Processing is done on the client-side, so larger logs may take (e.g., 10s) time to load. Loading may pause or slow if you do not have the window focsed.
